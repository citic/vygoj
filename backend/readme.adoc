= Vygoj Backend

The Vygoj Backend is a Code Execution Service because provides a web service to allow web applications to run source code into a sandboxed environment. It supports tests for concurrent programming. Distributed programming may be supported in the future. The following steps run it on a Debian-based distribution:

[source,bash]
----
# Install Docker and create a Debian image
$ cd engine
$ sudo make install  # If Docker is not already installed
$ make image
$ cd ..

# Install dependencies and run the backend. Requires Python 3
$ sudo apt install python3
$ make release
----



[user_manual]
== User manual

NOTE: A running Docker server is needed before running the backend. Read link:engine/readme.adoc[VygOJ Engine's documentation] to install and run the Docker server before continuing.

The backend is developed in Python and requires Flask. A `Makefile` is provided to ease this process on Debian-based distributions. The default rule creates a Python virtual environment, installs dependencies, and run the backend for debugging:

[source,bash]
----
$ make
----

In production server, you can run the backend with no debug reporting:

[source,bash]
----
$ make release
----

For keeping the backend server running in background even after logging out from the terminal, you can use `gunicorn`:

[source,bash]
----
$ make server
----

The server writes its logs (`access.log`, `error.log`) and its process id (`gunicorn.pid`) in the `data/` folder, which is ignored by Git. Stop the server with `make stop`.

You can remove the virtual environment when it is no longer needed:

[source,bash]
----
$ make clean
----

[security]
== Security

The backend runs code written by untrusted users, so each submission runs in a disposable container created with restrictions (see `create_container()` in `src/execution.py`):

* Unprivileged `student` user, all Linux capabilities dropped, `no-new-privileges`, and the default seccomp profile of Docker. The container never runs in privileged mode.
* No network.
* Limits of memory (512 MiB without swap), processes and threads (512), CPUs (2), file size (64 MiB), open files (4096), and a 64 MiB `/tmp` kept in memory.
* Every command has a time limit, its output is truncated to 1 MiB per stream, and student processes left in background are killed after each test case. The whole submission is killed after 100 seconds.
* Command line arguments of test cases are split as a shell would, but they are never interpreted by a shell.

Requests to `/run` larger than 16 MiB, or with invalid JSON, types, languages, or sizes, are rejected with a 4xx status. The backend has no authentication: it must not be reachable from the Internet, only from the frontend.

Containers have the label `vygoj=engine`. If a backend process is killed during a submission, its container may remain; remove it with:

[source,bash]
----
$ docker rm -f $(docker ps -aq --filter label=vygoj=engine)
----
