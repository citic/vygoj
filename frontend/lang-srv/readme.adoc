= VygOJ language server

The language server gives the code editor of the problem page the suggestions and parameter hints of a real language server, such as `clangd` for C: typing `fge` suggests `fgets` with its parameters and documentation, typing `fgets(line, ` highlights its parameter `int n`, and choosing a function of a header that the code does not include adds its `#include`. Without it, the editor only suggests the words already written in the code.

It is a process of its own, besides the frontend and the backend:

----
Browser (Monaco)                    Frontend (8080)                 Language server (7070)        Docker
1. POST {action: 'lang_server'} ──► checks the session and that
                                ◄── the user may open the problem:
                                    {url, key valid for 60 s}
2. WebSocket to url, sends key  ──────────────────────────────────► checks the origin and the key
                                                                    starts a container ─────────► clangd
3. ⇄ LSP messages (suggestions, parameter hints) ⇄ ────────────────── filters and passes them ⇄ ─── (no network)
4. the page closes              ──────────────────────────────────► removes the container
----

The editor (`static/js/components/lang-client.js`) talks the Language Server Protocol (LSP) through a WebSocket. Each editor gets its own container, where the language server reads the code that the editor sends; it never runs that code. Its source code is in `src/main.py`, its settings in `config/`, and its Docker image in `image/`.

== Installation

The language server needs Docker, like the backend (see `backend/engine/readme.adoc` to install it), and the user that runs it must be able to use Docker (e.g. be in the `docker` group). Docker gives that user the powers of `root`, so use a user of its own for the language server, not the one of the frontend. It may run in the computer of the frontend or in another one that browsers reach.

First, build the image of the containers, with the language servers and the headers of the libraries that solutions include. Rebuild it regularly to receive security updates:

[source,console]
----
cd vygoj/frontend/lang-srv
make image
----

Second, install the Python dependencies:

[source,console]
----
make install
----

Third, configure the language server. It loads the default settings of `config/defaults.py`, which explains each one, and replaces them with the ones of `config/config.py` (git-ignored). At least, set the secret shared with the frontend, and the address of the frontend as browsers write it:

[source,console]
----
cd config
echo "LANG_SERVER_SECRET = '$(python3 -c 'import secrets; print(secrets.token_hex(32))')'" >> config.py
echo "ORIGINS = ['https://vygoj.citic.ucr.ac.cr']" >> config.py
chmod 600 config.py
----

Fourth, tell the frontend where the language server is, in `frontend/config/config.py`: its address as browsers reach it (`LANG_SERVER`, with the IP or host name and the port, 7070 by default), and the same secret (`LANG_SERVER_SECRET`). Restart the frontend after changing them:

[source,python]
----
LANG_SERVER = 'ws://localhost:7070'
LANG_SERVER_SECRET = 'the same secret of frontend/lang-srv/config/config.py'
----

== Running

The rules of `common/Makefile` work here too. The language server listens on port 7070 of every address (`HOST` and `PORT` in its `Makefile`):

[source,console]
----
make          # debug server
make server   # gunicorn daemon, logs and pid file in data/
make stop     # stop the gunicorn daemon
make lint     # Pylint
----

Each connection keeps a thread of gunicorn busy while the student edits code, so the `Makefile` gives gunicorn one worker of 120 threads for 100 editors at the same time (`MAX_SESSIONS` in `config/defaults.py`): the spare threads refuse the connections beyond it. The worker is only one because it counts the sessions of each user in its memory. Raise both together if needed, and the memory of the computer with them: each container may use up to `CONTAINER_MEMORY`.

The debug server of Flask (`make`) writes an HTTP answer on a connection that the browser closed, and the console of the browser reports `Invalid frame header` when the editor changes its language. Gunicorn (`make server`) does not.

Behind Apache with HTTPS (see the reverse proxy section of `frontend/readme.adoc`), pass the WebSocket connections of a path to the language server. Enable the module, and add the line before the `ProxyPass /` of the frontend, because Apache uses the first one that matches:

[source,config]
----
# sudo a2enmod proxy_wstunnel
ProxyPass /lang-srv/ ws://127.0.0.1:7070/
----

Then the frontend uses `LANG_SERVER = 'wss://vygoj.citic.ucr.ac.cr/lang-srv/'`, and the language server may listen only on `127.0.0.1` (`make server HOST=127.0.0.1`).

== Security

The language server reads code of untrusted users, and anyone in the Internet may try to connect to it:

* *Only users who may open a problem connect.* The frontend gives a key only after checking the session in the database and that the user may enter the course of the problem (the professor, its students, and administrators), and only for a language of the problem. The key is signed with `LANG_SERVER_SECRET`, which only the frontend and the language server know, and it expires in a minute (`KEY_MAX_AGE`). The session cookie of the frontend is not used: it cannot be revoked, so a suspended user could keep using it. The server refuses to start without a secret of at least 32 characters.
* *Pages of other sites cannot connect.* Browsers do not apply CORS to WebSockets, so the server checks the `Origin` header against `ORIGINS`, and the key is only given to a POST with the CSRF token of the session.
* *The key travels in the first message*, not in the URL, so it is not written in the logs of proxies. A connection without it closes in 3 seconds (`KEY_TIMEOUT` in `src/main.py`), and one that sends a message longer than 1 MiB (`MAX_MESSAGE_SIZE`), even before the key, closes while it arrives. Connections without a key still keep a thread busy for those seconds, so behind Apache limit the connections of each IP address too (e.g. `mod_qos` or the firewall).
* *Each editor gets a container* without network, capabilities, nor writable files but a small `/tmp` in memory, that runs as the user `nobody` without new privileges, with limits of memory, CPU, and processes (`CONTAINER_*`). A language server reads the files that the code includes (e.g. `#include "/etc/passwd"`), but it can only read the files of the image.
* *Only some messages pass.* The editor may only open and change its code, and ask for suggestions and parameter hints (`CLIENT_METHODS` in `src/main.py`); other messages, e.g. commands of the server, are dropped, and a malformed one closes the connection. The server writes the parameters of the start of the language server: its folder is `/home/student` and its options are the ones of `INITIALIZATION_OPTIONS`, never the ones of the editor. Messages of the language server are limited to 16 MiB. The language server answers the requests of the language server itself, and drops its diagnostics: the backend reports the errors of the code.
* *Sessions are bounded*: `MAX_SESSIONS` in total and `MAX_USER_SESSIONS` per user, even when a user opens many connections at the same time with one key. A connection closes after `IDLE_TIMEOUT` without messages, and the container stops by itself after `MAX_DURATION`, or when its language server reads the end of its input, even if the language server process was killed. The editor connects again with a new key when the student types after that.

Containers have the label `vygoj=lang-srv`. To remove leaked ones:

[source,console]
----
docker rm -f $(docker ps -aq --filter label=vygoj=lang-srv)
----

== Adding a language

. Install its language server in `image/Dockerfile`, and its options in a configuration file of the image if it needs them (e.g. `image/clangd.yaml`, with the standard that the backend compiles with). Then run `make image`.
. Add its command to `LANGUAGES` in `config/defaults.py`, by the name of the language in VygOJ (e.g. `'C'`), and its options to `INITIALIZATION_OPTIONS` if it needs them.
. Add the name of its solution file to `LANGUAGES` in `static/js/components/lang-client.js`, as the backend names it (e.g. `solution.c`), with the name of the language in LSP (e.g. `c`).
