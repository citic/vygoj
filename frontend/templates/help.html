Hilos en C++

En C++ se puede crear un hilo secundario al instanciar un objeto de la clase std::thread(routine). El constructor del objeto recibe la rutina que se ejecutará en la pila del nuevo hilo de ejecución. Si la rutina recibe parámetros, los argumentos se pueden proveer en el constructor. El hilo principal puede esperar al hilo secundario invocando su método join().

#include <thread>

void routine(char ch) { ... }  // secondary thread routine

int main() {  // main thread
  std::thread secondary(routine, 'a');
  ...
  secondary.join();
}

Si se quiere crear un equipo de hilos y almacenar los objetos en una colección, no se puede usar el método push_back(), dado que los hilos no se pueden copiar. En su lugar se puede usar el método emplace_back() de la colección, el cual crea directamente al objeto dentro del contenedor sin hacer copias. Por ejemplo:

void routine(size_t thread_number) { ... }

int main() {
  std::vector<std::thread> threads;
  for (size_t i = 0; i < 10; ++i) {
    threads.emplace_back(routine, i);
  }
  ...
  for (std::thread& secondary : threads) {  
    secondary.join();
  }
}

Exclusión mutua en C++

C++ ofrece la clase std::mutex con los métodos lock() y unlock() para encerrar regiones críticas de código. Por ejemplo:

#include <mutex>
std::mutex can_access_it;

void routine() {
  can_access_it.lock();  // lock the mutex
  // critical section
  can_access_it.unlock();  // unlock the mutex
}

Semáforos en C++

C++20 ofrece dos clases para semáforos: std::counting_semaphore y std::binary_semaphore. El primero es un semáforo regular, que puede adquirir cualquier valor no negativo. El std::binary_semaphore ofrece la misma funcionalidad que un std::mutex con la diferencia de que un std::mutex tiene dueño, mientras que un std::binary_semaphore no.

Para decrementar o esperar (wait) en un semáforo de C++ se usa el método acquire() y para incrementar (signal) un semáforo se usa el método release(). Por ejemplo:

#include <semaphore>
std::counting_semaphore can_do_task(0);

void routine() {
  can_do_task.acquire();  // wait/decrement the semaphore
  task()
  can_do_task.release();  // signal/increment/post the semaphore
}

Barreras en C++

C++20 ofrece barreras con el objeto std::barrier, cuyo constructor recibe la cantidad de hilos que deben llegar a la barrera para que esta se levante. Cuando un hilo llega a la barrera puede invocar el método arrive_and_wait(). Por ejemplo:

#include <barrier>
std::barrier start_race(3);

void routine() {
  start_race.arrive_and_wait();  // wait at the barrier
  run();
}

Violaciones de atomicidad

Una violación de atomicidad ocurre cuando instrucciones que se deben ejecutar juntas como una unidad, son separadas, violando su ejecución como una transacción o "unidad atómica". Esta separación permite que se traslapen con la ejecución de otras instrucciones por parte de otros hilos de ejecución.

Por ejemplo, el siguiente código tiene una violación de atomicidad porque el hilo obtiene el mutex, copia la cantidad de elementos del vector y libera el mutex. En el entretanto escoge un índice al azar. Cuando vuelve a obtener el mutex supone que el estado del vector es el mismo que la primera vez que obtuvo el mutex. Sin embargo, en el entretanto otro hilo pudo modificar el vector, y el índice escogido al azar podría referirse a otro elemento o salirse de rango.

std::vector<double> values;
std::mutex can_access_values;

void routine() {
  can_access_values.lock();
    const size_t size = values.size();
  can_access_values.unlock();

  const size_t index = rand() % size;

  can_access_values.lock();
    const double& my_value = values[index];
  can_access_values.unlock();

  std::cout << my_value << std::endl;
}

Para evitar la violación de atomicidad, se debe extender la región crítica. Es decir, obtener el mutex, escoger un índice al azar, acceder al vector para obtener el elemento al azar, el cual se puede copiar a una variable, y finalmente liberar el mutex. De esta forma, el estado del vector no cambia mientras ocurren estas operaciones, como si fueran una unidad o transacción:

void routine() {
  can_access_values.lock();
    const size_t size = values.size();
    const size_t index = rand() % size;
    const double my_value = values[index];
  can_access_values.unlock();

  std::cout << my_value << std::endl;
}

Instrucciones atómicas en C++

No siempre es necesario crear un mutex para proteger una única variable. Los procesadores multi-núcleo proveen instrucciones atómicas, las cuales garantizan que sólo un núcleo o CPU la puede estar ejecutando a la vez. Eso evita condiciones de carrera de una forma muy eficiente.

Si en una variable se quieren usar instrucciones atómicas, en C++ se declara esa variable con la plantilla std::atomic<Type> var;. La plantilla construye un "objeto" que tiene algunos operadores sobrecargados, como asignación (=), incremento (++), operadores combinados (como -=), entre otros. La implementación de esos operadores usan instrucciones atómicas del procesador multinúcleo.

Por ejemplo, el siguiente código crea dos contadores. El primero es un contador normal que sufrirá condiciones de carrera. El segundo es un contador protegido por instrucciones atómicas. Es decir, sólo un hilo lo puede incrementar a la vez. Si un hilo trata de incrementarlo y otro lo está haciendo, su núcleo de CPU esperará unos pocos ciclos de reloj a que el otro hilo termine la operación atómica. Si se hubiera usado un mutex, el hilo que trata de bloquear el mutex y no lo consigue, es retirado de la CPU y enviado a una cola de espera. Pasarán miles de ciclos de reloj hasta que el hilo recupere una CPU y continúe su incremento.

#include <atomic>

long normal_counter = 0;
std::atomic<long> atomic_counter(0);

void routine() {
  for (size_t i = 0; i < 10000; ++i) {
    ++normal_counter;  // increment normal counter
    ++atomic_counter;  // increment atomic counter
  }
}

int main() {
  std::thread thr1(routine), thr2(routine);
  thr1.join();
  thr2.join();
  std::cout << normal_counter << ' ' << atomic_counter;
  // Possible output: 19701 20000
}

Instrucciones atómicas en C

Hay varias formas de trabajar con instrucciones atómicas en C. La palabra reservada _Atomic de C11 es muy similar a las variables atómicas de C++. La instrucción _Atomic(Type) var; indica al compilador que los operadores que se usen con la variable, deben traducirse en el código objeto a operaciones atómicas del procesador multinúcleo. El siguiente código replica el ejemplo de los contadores en C:

#include <pthread.h>

long normal_counter = 0;
_Atomic(long) atomic_counter = 0;

void* routine(void* arg) {
  for (size_t i = 0; i < 10000; ++i) {
    ++normal_counter;  // increment normal counter
    ++atomic_counter;  // increment atomic counter
  }
}

int main() {
  pthread_t thr1, thr2;
  pthread_create(&thr1, NULL, routine, NULL);
  pthread_create(&thr2, NULL, routine, NULL);
  pthread_join(thr1, NULL);
  pthread_join(thr2, NULL);
  printf("%ld %ld\n", normal_counter, atomic_counter);
  // Possible output: 18954 20000
}
