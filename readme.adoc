**VygOJ**, Vygotsky Online Judge, is an educative tool designed to support software requirements derived from Sociocultural Constructivism theory. VygOJ combines features from other tools such as Online Programming Judges (OJ), Learning Management Systems (LMS), and Massive Open Online Courses (MOOC). As a distinctive feature, VygOJ supports the concurrent programming paradigm.

This document explains what VygOJ is made of, and how to install, configure, run, stop, and update it. It is written for the IT staff who install it and for the directors and professors who decide how to use it. Developers find the design of VygOJ in link:design/readme.adoc[design/readme.adoc].


[[architecture]]
== Architecture

An *online programming judge* is a software that provides "verdicts" about the correctness and efficiency of other computer programs. These verdicts are generated by using software testing. VygOJ is an online judge for educative goals that supports the concurrent programming paradigm. Most online judges are designed for competitive programming and recruiting.

VygOJ is made of the layers shown in the UML component diagram of <<fig_architecture>>. Each «component» is a program that talks with the others through the network, so they may run in one computer or in several ones; the folder of its source code is in monospaced font. Circles are the browsers of the users and the containers that the programs create. Each connection joins the program that offers a service (the ball) with the one that uses it (the socket), and names its protocol.

[#fig_architecture]
.Software architecture and project folders
image::docs/img/architecture.svg[]

VygOJ users are professors, students, teaching assistants, directors, and administrators. They use a _web browser_ to access these programs:

Frontend (`frontend/`)::
The web application, the only program that users reach. It shows courses and problems, receives the solutions of students, and keeps the users, their progress, and their activity. It stores its data in a PostgreSQL database and in a data folder. Professors write their courses in git repositories, which the frontend copies from Git hosts such as GitHub or GitLab. Users may log in with the account of their institution (single sign-on).

Backend (`backend/`)::
The code execution service. The frontend never runs the code of students: it sends it to a backend, which compiles it, runs it with the test cases of the problem, and answers the verdicts. Each solution runs in a disposable, isolated container (the *engine*, `backend/engine/`), which is created for each solution and destroyed after it. Several backends can share the work: the frontend sends each solution to one of them at random.

Language server (`frontend/langserv/`)::
Optional. It gives the code editor suggestions and parameter hints as the student types, as a professional editor does. It never runs the code. Without it, the editor only suggests the words already written in the code.

Database::
A PostgreSQL server, in the computer of the frontend or in another one.

[[requirements]]
== Requirements

VygOJ runs on Linux. These instructions give the commands of the main families of distributions: Debian (and Ubuntu), Fedora and Red Hat Enterprise Linux (RHEL, Rocky, Alma), and Arch. Every computer needs:

* Git, Make, Python 3.9 or newer, and the OpenSSH client, in the computers of the programs of VygOJ.
* A user for each program of VygOJ that it runs (see <<users>>).
* Asciidoctor, which converts the problem statements, and a web server as reverse proxy, Apache or nginx, only in the computer of the frontend.
* Docker, only in the computers of the backend and the language server.
* PostgreSQL, only in the computer of the database.

The frontend should be reachable from the Internet (or from the network of the institution), with a domain name and an HTTPS certificate. The other computers do not need to be reachable from the Internet: only the frontend connects to them, so they may have private addresses.

A small course may run every program in one computer. Larger courses spread them in several computers (see <<configuration>>): the backends need CPU and memory to run the solutions of many students at the same time, and the language server needs memory for the editors open at the same time.


[[install]]
== Installation

[[packages]]
=== Dependencies

Install the packages that VygOJ needs with the package manager of the distribution. These commands need administration permissions (`sudo`); the `Makefile` of VygOJ never installs packages of the system, so its rules run with the user of each program, without `sudo`. In each computer, run the commands of the programs that it has: the commands of _All_ are for the computers of the frontend, the backend, and the language server, and the computer of the database only needs the ones of _Database_.

[[packages_debian]]
==== Debian, Ubuntu

[source,sh]
----
# All
sudo apt update
sudo apt install git make openssh-client python3 python3-pip python3-venv

# Frontend: problem statements and certificates
sudo apt install asciidoctor certbot
sudo apt install apache2 python3-certbot-apache    # Apache as reverse proxy, or
sudo apt install nginx python3-certbot-nginx       # nginx as reverse proxy

# Backend and language server
sudo apt install docker.io

# Database
sudo apt install postgresql
----

[[packages_fedora]]
==== Fedora, RHEL, Rocky, Alma

RHEL, Rocky, and Alma need version 9 or newer, and the EPEL repository for Asciidoctor and `certbot` (`sudo dnf install epel-release` in Rocky and Alma). They do not include Docker, so it is installed from the repository of Docker; Fedora uses its own package, `moby-engine`, instead.

[source,sh]
----
# All
sudo dnf install git make openssh-clients python3 python3-pip

# Frontend: problem statements and certificates
sudo dnf install rubygem-asciidoctor certbot
sudo dnf install httpd mod_ssl python3-certbot-apache    # Apache as reverse proxy, or
sudo systemctl enable --now httpd
sudo dnf install nginx python3-certbot-nginx             # nginx as reverse proxy
sudo systemctl enable --now nginx

# Backend and language server, in Fedora
sudo dnf install moby-engine
sudo systemctl enable --now docker

# Backend and language server, in RHEL, Rocky, and Alma
sudo dnf install dnf-plugins-core
sudo dnf config-manager --add-repo https://download.docker.com/linux/rhel/docker-ce.repo
sudo dnf install docker-ce docker-ce-cli containerd.io docker-buildx-plugin
sudo systemctl enable --now docker

# Database
sudo dnf install postgresql-server
sudo postgresql-setup --initdb
sudo systemctl enable --now postgresql
----

[[packages_arch]]
==== Arch

The options of `initdb` let local users connect to the database only as themselves, and other computers only with a password.

[source,sh]
----
# All
sudo pacman -Syu --needed git make openssh python python-pip

# Frontend: problem statements and certificates
sudo pacman -S --needed asciidoctor certbot
sudo pacman -S --needed apache certbot-apache    # Apache as reverse proxy, or
sudo systemctl enable --now httpd
sudo pacman -S --needed nginx certbot-nginx      # nginx as reverse proxy
sudo systemctl enable --now nginx

# Backend and language server
sudo pacman -S --needed docker
sudo systemctl enable --now docker

# Database
sudo pacman -S --needed postgresql
sudo -iu postgres initdb -D /var/lib/postgres/data --locale=C.UTF-8 --encoding=UTF8 --auth-local=peer --auth-host=scram-sha-256
sudo systemctl enable --now postgresql
----

[[packages_macos]]
==== macOS (only for development)

Git, Make, and Python come with the command line tools of Xcode, and the other programs are installed with https://brew.sh[Homebrew]. Open Docker Desktop once after installing it, to accept its license. A reverse proxy is not needed for development.

[source,sh]
----
# All
xcode-select --install

# Frontend
brew install asciidoctor

# Backend and language server
brew install docker-desktop

# Database
brew install postgresql@18
brew services start postgresql@18
----

The Docker of the distribution is enough for VygOJ. For its latest version, install it from the repository of Docker instead, following the https://docs.docker.com/engine/install/[guide of Docker] for each distribution.

[[users]]
=== Users

Each program of VygOJ runs with a Linux user of its own. The backend and the language server create Docker containers, and a user that can use Docker has the powers of `root`. So only the users of the backend and the language server are in the `docker` group, and the frontend, which the whole Internet reaches, is not: whoever breaks into it gets no `root` powers. The database runs with the user `postgres`, which its package creates.

[cols="1,1,1"]
|===
| Program | User | In the `docker` group

| Frontend | `vygoj-frontend` | No
| Backend | `vygoj-backend` | Yes
| Language server | `vygoj-langserv` | Yes
|===

In each computer, after installing its dependencies (<<packages>>), create the users of the programs that it runs. The users have no password: the administrators of the computer become them with `sudo`.

[source,sh]
----
# Frontend
sudo useradd -m -s /bin/bash vygoj-frontend

# Backend
sudo useradd -m -s /bin/bash vygoj-backend
sudo usermod -aG docker vygoj-backend

# Language server
sudo useradd -m -s /bin/bash vygoj-langserv
sudo usermod -aG docker vygoj-langserv
----

[[install_programs]]
=== Installing each program

Each user has its own copy of VygOJ in its home folder. Keep the whole repository: the programs share the code of the `common/` folder. For example, for the backend:

[source,sh]
----
sudo -iu vygoj-backend
git clone https://github.com/citic/vygoj
----

Then install each program with its user, following its own document:

* link:backend/readme.adoc[Backend]: the image of the engine, and the backend.
* link:frontend/readme.adoc[Frontend]: the database, the configuration, and the first administrator.
* link:frontend/langserv/readme.adoc[Language server]: the image of its containers and its configuration.

Each program has a `Makefile`: `make install` installs it, and `make` runs it for tests. In production, each program runs as a system service (<<running>>).


[[configuration]]
== Configuration in several computers

By default, the programs look for each other in the same computer (`localhost`). This section shows how to connect them when each one runs in its own computer. The example has five computers in a private network, and the site is published as `https://vygoj.citic.ucr.ac.cr`; change the addresses and the domain name to yours:

[cols="1,1,1,2",options="header"]
|===
| Address | Computer | Port | Accepts connections from

| 10.0.0.1 | Frontend, with Apache or nginx | 80, 443 | The Internet
| 10.0.0.2 | Database (PostgreSQL) | 5432 | 10.0.0.1 only
| 10.0.0.3 | Language server | 7070 | 10.0.0.1 only
| 10.0.0.4 | Backend 1 | 9090 | 10.0.0.1 only
| 10.0.0.5 | Backend 2 | 9090 | 10.0.0.1 only
|===

[#fig_deployment]
.Installation in five computers (link:docs/img/deployment.mmd[diagram source])
[mermaid]
....
include::docs/img/deployment.mmd[]
....

Each of the five computers, the frontend included, has a firewall that accepts only the connections of the table, and SSH for its administration. The firewall filters only the connections that other computers open: those that the computer opens itself, and their answers, are accepted, so `apt`, `dnf`, `pacman`, `git pull`, `pip`, and Docker still download from the Internet.

Debian, Ubuntu, and Arch use the `ufw` firewall, and Fedora and RHEL use `firewalld`, which is already installed and enabled, and accepts SSH. Install `ufw` in each computer before configuring it:

[source,sh]
----
# Debian (Ubuntu already includes ufw, disabled until "sudo ufw enable")
sudo apt install ufw

# Arch
sudo pacman -S --needed ufw
sudo systemctl enable ufw    # Start it at boot; "sudo ufw enable" starts it now
----

The section of each computer, below, gives its own firewall rules, for `ufw` and for `firewalld`: run only the ones of its distribution.

Browsers only connect to the frontend computer. Its web server, Apache or nginx, serves the pages of the frontend and passes the connections of the code editors to the language server, so the language server keeps a private address. The connections inside the private network are not encrypted, so it must be a network that only these computers use. Configure the computers in this order, because each one needs the previous ones.

[[config_database]]
=== Database: 10.0.0.2

Install and start PostgreSQL with the commands of _Database_ of the distribution (<<packages>>). Then create the user of the frontend, with a password, and its database. Use a long random password of letters and digits (other characters must be escaped in the address of the database). Nobody types it to log in: it is copied once, to the address of the database in the configuration of the frontend (<<config_frontend>>), so it does not need to be easy to remember:

[source,sh]
----
openssl rand -hex 32    # Generate a random password; paste it when createuser asks for it
sudo -u postgres createuser --pwprompt vygoj-frontend
sudo -u postgres createdb -O vygoj-frontend vygoj
----

The configuration of PostgreSQL is in a folder that depends on the distribution:

[cols="1,2",options="header"]
|===
| Distribution | Folder of the configuration

| Debian, Ubuntu | `/etc/postgresql/<version>/main/`
| Fedora, RHEL | `/var/lib/pgsql/data/`
| Arch | `/var/lib/postgres/data/`
|===

PostgreSQL only accepts connections from its own computer by default. Let it listen on its private address, in `postgresql.conf` of that folder:

[source,config]
----
listen_addresses = 'localhost,10.0.0.2'
----

Let only the frontend computer connect to the database, with the password, adding this line at the end of `pg_hba.conf` of the same folder:

[source,config]
----
# type  database  user            address        method
host    vygoj     vygoj-frontend  10.0.0.1/32    scram-sha-256
----

Restart PostgreSQL, and let the firewall accept only the frontend in its port:

[source,sh]
----
sudo systemctl restart postgresql

# Debian, Ubuntu, and Arch: accept SSH, and the port 5432 only from the frontend
sudo ufw allow ssh
sudo ufw allow from 10.0.0.1 to any port 5432 proto tcp
sudo ufw enable

# Fedora and RHEL: accept the port 5432 only from the frontend (SSH is already accepted);
# --permanent saves the rule, and --reload applies it
sudo firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=10.0.0.1 port port=5432 protocol=tcp accept'
sudo firewall-cmd --reload
----

[[config_backends]]
=== Backends: 10.0.0.4 and 10.0.0.5

The backend has no passwords: whoever reaches its port can run code in it. So it listens only on its private address, and the firewall accepts only the frontend. Follow these steps in 10.0.0.4, and then in 10.0.0.5 with its own address.

First, install the backend with its user, `vygoj-backend`: the image of the engine and `make install` (see link:backend/readme.adoc[its document]). Then, with an administrator user, let the firewall accept only the frontend:

[source,sh]
----
# Debian, Ubuntu, and Arch: accept SSH, and the port 9090 only from the frontend
sudo ufw allow ssh
sudo ufw allow from 10.0.0.1 to any port 9090 proto tcp
sudo ufw enable

# Fedora and RHEL: accept the port 9090 only from the frontend (SSH is already accepted)
sudo firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=10.0.0.1 port port=9090 protocol=tcp accept'
sudo firewall-cmd --reload
----

Install the service of the backend, which runs it when the computer boots (<<running>>), and open the editor of its changes:

[source,sh]
----
sudo cp ~vygoj-backend/vygoj/backend/vygoj-backend.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl edit vygoj-backend
----

The editor shows two parts. At the top there is an empty space, above the comment `\### Edits/Lines below this comment will be discarded`: write there these three lines, which make the backend listen only on its private address. Below that comment, the whole service file of VygOJ is shown commented out, only for reference: do not change it, because the editor discards those lines.

[source,config]
----
[Service]
ExecStart=
ExecStart=/usr/bin/make service HOST=10.0.0.4
----

The empty `ExecStart=` is needed: it removes the command of the service file, because a service has only one, and the next line gives the new one. Save and close the editor. The change is kept apart from the file of VygOJ, in `/etc/systemd/system/vygoj-backend.service.d/override.conf`, so updates do not undo it. Then start the service, and check that it listens on its private address:

[source,sh]
----
sudo systemctl enable --now vygoj-backend
systemctl status vygoj-backend      # active (running)
ss -tln | grep 9090                 # 10.0.0.4:9090, not 0.0.0.0:9090
----

[[config_langserv]]
=== Language server: 10.0.0.3

The language server listens only on its private address, and the firewall accepts only the frontend. First, install it with its user, `vygoj-langserv`: the image of its containers and `make install` (see link:frontend/langserv/readme.adoc[its document]). `make install` writes a random `LANG_SERVER_SECRET` in `frontend/langserv/config/config.py`; keep it, because the frontend will copy it (<<config_frontend>>). Add the address of the site to that file:

[source,python]
----
# The address of the site, as users type it in their browsers
ORIGINS = ['https://vygoj.citic.ucr.ac.cr']
----

Then, with an administrator user, let the firewall accept only the frontend:

[source,sh]
----
# Debian, Ubuntu, and Arch: accept SSH, and the port 7070 only from the frontend
sudo ufw allow ssh
sudo ufw allow from 10.0.0.1 to any port 7070 proto tcp
sudo ufw enable

# Fedora and RHEL: accept the port 7070 only from the frontend (SSH is already accepted)
sudo firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=10.0.0.1 port port=7070 protocol=tcp accept'
sudo firewall-cmd --reload
----

Install its service, and open the editor of its changes:

[source,sh]
----
sudo cp ~vygoj-langserv/vygoj/frontend/langserv/vygoj-langserv.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl edit vygoj-langserv
----

As in the backends, write these three lines in the empty space at the top of the editor, above the comment `### Edits below this comment will be discarded`, and save:

[source,config]
----
[Service]
ExecStart=
ExecStart=/usr/bin/make service HOST=10.0.0.3
----

Then start the service, and check that it listens on its private address:

[source,sh]
----
sudo systemctl enable --now vygoj-langserv
systemctl status vygoj-langserv     # active (running)
ss -tln | grep 7070                 # 10.0.0.3:7070, not 0.0.0.0:7070
----

[[config_frontend]]
=== Frontend: 10.0.0.1

First, install the frontend with its user, `vygoj-frontend` (see link:frontend/readme.adoc[its document]), and skip the installation of PostgreSQL, which is in another computer. These are the settings of `frontend/config/config.py` that connect it to the other computers. `make install` already wrote the secrets in that file: keep `SECRET_KEY`, and replace `LANG_SERVER_SECRET` with the one of the language server:

[source,python]
----
# Folder of the repos of the users and the activity log
DATA_FOLDER = '/home/vygoj-frontend/vygdata'
# Database: user, password, address, and name
SQLALCHEMY_DATABASE_URI = 'postgresql+psycopg://vygoj-frontend:the-password@10.0.0.2/vygoj'
# Backends: each solution goes to one of them, chosen at random
BACKENDS = ['http://10.0.0.4:9090', 'http://10.0.0.5:9090']
# Language server, through the reverse proxy of this computer (see below)
LANG_SERVERS = ['wss://vygoj.citic.ucr.ac.cr/langserv/']
# The same secret as in frontend/langserv/config/config.py of the language server (10.0.0.3)
LANG_SERVER_SECRET = 'copy here the LANG_SERVER_SECRET of the language server'
# Address of the site, and the reverse proxy between the users and the frontend
SITE_URL = 'https://vygoj.citic.ucr.ac.cr'
TRUSTED_PROXIES = 1
----

The file has the password of the database, so only its owner may read it (`make install` creates it that way). Check that the frontend computer reaches the others: the backends answer their status, and `make users` creates the tables in the database:

[source,sh]
----
curl http://10.0.0.4:9090/status
curl http://10.0.0.5:9090/status
cd ~/vygoj/frontend && make users
----

Then, with an administrator user, let the firewall accept the Internet only in the ports of the reverse proxy:

[source,sh]
----
# Debian, Ubuntu, and Arch: accept SSH, and HTTP and HTTPS from anywhere
sudo ufw allow ssh
sudo ufw allow 80,443/tcp
sudo ufw enable

# Fedora and RHEL: accept HTTP and HTTPS from anywhere (SSH is already accepted)
sudo firewall-cmd --permanent --add-service=http --add-service=https
sudo firewall-cmd --reload
----

Install its service, and open the editor of its changes:

[source,sh]
----
sudo cp ~vygoj-frontend/vygoj/frontend/vygoj-frontend.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl edit vygoj-frontend
----

The frontend listens only on `127.0.0.1`, because the reverse proxy is in the same computer. As in the backends, write these three lines in the empty space at the top of the editor, above the comment `### Edits below this comment will be discarded`, and save:

[source,config]
----
[Service]
ExecStart=
ExecStart=/usr/bin/make service HOST=127.0.0.1
----

Then start the service, and check that it listens on `127.0.0.1`:

[source,sh]
----
sudo systemctl enable --now vygoj-frontend
systemctl status vygoj-frontend     # active (running)
ss -tln | grep 8080                 # 127.0.0.1:8080, not 0.0.0.0:8080
----

Last, configure Apache or nginx as the link:frontend/readme.adoc#reverse_proxy[reverse proxy] of the frontend, with its certificate, and make it pass the connections of the code editors to the language server, as the link:frontend/langserv/readme.adoc#reverse_proxy[language server] shows, with its address: in Apache, this line before its `ProxyPass /`; in nginx, a `location /langserv/` block with `proxy_pass http://10.0.0.3:7070/;`.

[source,config]
----
ProxyPass /langserv/ ws://10.0.0.3:7070/
----

The frontend also connects to the Internet: to the Git hosts of the repositories of professors and students (SSH, port 22), and to the single sign-on provider, if any (HTTPS). The backends and the language server only need the Internet to build or update their images.

To add a backend later, install it as the others, add its address to `BACKENDS`, and restart the frontend. To add language servers, see link:frontend/langserv/readme.adoc[its document].


[[running]]
== Running the servers

In production, each program runs as a system service of systemd, which starts it when the computer boots, starts it again if it fails, and keeps its log. The service of each program is described in a file of its folder: `frontend/vygoj-frontend.service`, `backend/vygoj-backend.service`, and `frontend/langserv/vygoj-langserv.service`. They expect the copy of VygOJ in the home folder of the user of the program (e.g. `/home/vygoj-backend/vygoj`); change their paths if it is in another folder.

Install and start the service of each program in its computer (the sections of <<configuration>> already include these steps, for several computers). For example, for the backend:

[source,sh]
----
sudo cp ~vygoj-backend/vygoj/backend/vygoj-backend.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now vygoj-backend
----

Check that it is running, and read its log:

[source,sh]
----
systemctl status vygoj-backend           # is it running? its last log lines
journalctl -u vygoj-backend -f           # follow its log
----

Each program also runs without systemd, from its folder: `make` for tests (it stops with kbd:[Ctrl+C]), and `make server` in the background, with its logs in its `data/` folder. In one computer with the three programs, `make install`, `make image`, and `make` in the root folder install, build, and run the three at once, for tests (see link:design/readme.adoc[the design document]).


[[stopping]]
== Stopping the servers

Stop a service, or restart it, e.g. after changing its configuration:

[source,sh]
----
sudo systemctl stop vygoj-backend        # stop it, and remove the containers that it left
sudo systemctl restart vygoj-backend     # stop it and start it again
sudo systemctl disable vygoj-backend     # do not start it when the computer boots
----

A program started with `make server` stops with `make stop` in its folder.

Stopping the frontend makes the site unavailable. Stopping a backend lets the frontend keep working, but runs sent to it fail: remove it from `BACKENDS` first. Stopping the language server only removes the suggestions of the editor.


[[updating]]
== Updating the servers

To update a program, run `make update` in its folder with its user, and restart its service. `make update` gets the new code, installs the dependencies again, and rebuilds the image of the program, if it has one. For example, for the backend:

[source,sh]
----
sudo -iu vygoj-backend make -C vygoj/backend update
sudo systemctl restart vygoj-backend
----

The folders are `vygoj/frontend` for the frontend, and `vygoj/frontend/langserv` for the language server. Update the backends and the language servers before the frontend, which uses them. The frontend updates its database tables when it starts. Update every program at the same time: VygOJ is in development, and a new frontend may not work with an old backend.

Rebuild the images regularly (e.g. once a month), even without new versions of VygOJ, to receive the security updates of Debian: `make rebuild` in `backend/engine/` and in `frontend/langserv/`. Running solutions and editors keep working meanwhile.
