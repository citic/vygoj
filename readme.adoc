**VygOJ**, Vygotsky Online Judge, is an educative tool designed to support software requirements derived from Sociocultural Constructivism theory. VygOJ combines features from other tools such as Online Programming Judges (OJ), Learning Management Systems (LMS), and Massive Open Online Courses (MOOC). As a distinctive feature, VygOJ supports the concurrent programming paradigm.



[[architecture]]
== Architecture

An *online programming judge* is a software that provides "verdicts" about the correctness and efficiency of other computer programs. There verdics are generated by using software testing. VygOJ is an online judge for educative goals that support the concurrent programming paradigm. Most online judges are designed for competitive programming and recruiting.

This online judge is compound of the modules shown in <<fig_architecture>>. Colored boxes and circles are independent processes that intercomunicate through message passing. Folders where the source code is located for each module are shown in monospaced font.

[#fig_architecture]
.Software architecture and project folders
image::docs/img/architecture.svg[]

VygOJ users are professors, students, teaching assistants, and administrators. They use a _web browser_ to access the *Online Judge Web Application* module, namely *Frontend* for short. This module is a web server developed in Flask/Python and a web client using vanilla JavaScript. The frontend source code is the `frontend/` directory.

The web application does not run code from users. It captures that code and passes it to the *Code Execution Web Service*, called *Backend* for short. This is a REST web service that executes code in a cluster of computers. It provides verdicts about the correctness and efficiency of the given code using software testing methods. The frontend is able to communicate with multiple backends. If more than one backend is configured, the frontend randomly distributes the load among them.

For security reasons, the _Code Execution Service_ must run non-trusted code within an isolated environment. A *Code Execution Engine*, namely *Engine* for short, is conceptually a virtual machine (actually, a software container) that compiles the code and runs it without affecting other programs. An engine is created by the _web service_ for each program execution, and then destroyed. The _web service_ fetches the results of the program execution before it is destroyed.

The results of each executed program are fetched from the _frontend_ module and shown to the users. The _frontend_ module is not only an online judge, it is an educative tool that helps students to learn computer programming and teachers to manage their courses, monitor their students' progress, and more.

The _backend_ uses Docker containers as _code executions engines_. Currently it is not designed for efficiency, but for providing correctness and security of testing of concurrent programs. Efficiency may be addressed in future work.

[[install]]
== Quick installation

Frontend and backend are recommeded to be installed in different machines. You likely will want an Internet-accessible machine for the frontend (using a public network address). The backend does not need to be worldwide-accessible, only accessible from the frontend.


[[common_install]]
=== Common

VygOJ is designed to run in Unix-like environments. The following instructions are for Debian-based Linux distributions, but they can be adapted to other Unix-like systems. First install the required dependencies: Git for cloning, Make for building, and Python 3.9+ for running the server code.

[source,sh]
----
sudo apt update
sudo apt install git make python3 python3-pip python3-venv
----

Clone this repository in the machine where a module will run:

[source,sh]
----
git clone https://git.ucr.ac.cr/ecci/vygoj.git
----



[[backend_install]]
=== Backend

[source,sh]
----
cd backend/engine   # Install Docker
sudo make install   # Skip sudo for macOS
make image          # Create Docker image
cd ..               # Backend
make install        # Backend Python dependencies
----



[[frontend_install]]
=== Frontend

First install the Python dependencies:

[source,console]
----
cd vygoj/frontend
make install
----

Second, configure the frontend. Copy the example configuration file and edit it. Follow the instructions in the file. At least, you must provide an existing folder to store data and a list of backend servers.

[source,console]
----
cd vygoj/frontend/config
cp -n config-example.py config.py
nano config.py
----

Third, run the frontend as a production server:

[source,console]
----
cd vygoj/frontend
make server
----

If you need to stop the server, call `pkill gnunicorn`.
